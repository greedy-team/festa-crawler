# 🚀 [기능요청] 사이트맵 기반 후보 URL 탐색

📝 현재 문제점
---

후보 URL 탐색이 전적으로 웹 검색에 의존합니다. 검색 1건에 60초 이상 걸리고 구독 세션 한도를 소모하는데, 이 한도는 크롤러가 실제로 중단되는 원인입니다.

지금 시즌은 시드에 URL이 21곳 채워져 있어 탐색이 9곳만 돌았습니다. 문제는 다음 시즌입니다. 시드 URL 21개 중 19개가 주소에 연도가 박힌 특정 연도 글이라, 연도가 바뀌면 전부 검증에서 떨어지고 29곳 전부가 탐색으로 넘어갑니다. 29곳 × 60초면 30분 가까이 걸리고 중간에 한도에 걸릴 가능성이 높습니다.

한편 우리가 이미 출처로 쓰는 블로그들은 사이트맵을 열어두고 있습니다. 요청 1건으로 그 블로그의 전체 글 목록을 받을 수 있고, 티스토리 계열은 글 주소에 제목이 그대로 들어가 대학명과 연도를 주소만 보고 판별할 수 있습니다.

실측 결과입니다.

- 대상 블로그 5곳의 사이트맵에서 글 5260건 수집
- 대학 정식 표기가 주소에 그대로 들어간 것만 세면 시드 29곳 중 17곳 확보
- 요청 5건, LLM 호출 0회

주의할 점도 확인했습니다. 현재 실패 중인 3곳(숙명여대·동덕여대·삼육대)은 5개 블로그 어디에도 없습니다. 이 작업으로 커버리지는 늘지 않습니다. 얻는 것은 탐색 시간과 세션 한도 소모입니다.

블로그의 검색 기능은 쓸 수 없습니다. 대상 블로그 모두 robots.txt에서 검색 경로를 명시적으로 차단하고 있습니다. 사이트맵은 차단 목록에 없습니다.

🛠️ 해결 방안 / 제안 기능
---

시드 URL과 웹 검색 사이에 사이트맵 탐색 단계를 넣습니다.

- 시드에 URL이 있으면 지금처럼 그것을 먼저 시도합니다
- 실패하거나 URL이 없으면 사이트맵에서 후보를 찾아 시도합니다
- 사이트맵 후보가 모두 검증에 실패하면 그때 웹 검색을 호출합니다

웹 검색을 지연 호출하는 것이 핵심입니다. 사이트맵이 출처를 확보하면 검색을 아예 부르지 않으므로 그 대학의 60초와 세션 한도가 통째로 절약됩니다.

매칭은 엄격하게 합니다. 대학 정식 표기가 주소에 그대로 들어 있고 대상 연도가 있는 글만 후보로 봅니다. 줄임말과 어간 매칭은 쓰지 않습니다. 실측에서 줄임말은 순이득이 0이면서 부분 문자열 충돌을 만들었습니다. 성대가 경성대와 한성대를, 연대가 경연대회를, 한대가 유한대학교를 잡습니다. 어간 매칭은 다른 캠퍼스 글을 끌어오는데, 검증 단계가 대학명과 연도만 보기 때문에 잘못된 캠퍼스 라인업이 채택될 수 있습니다.

산출물의 출처 표기에 사이트맵 경로를 새로 추가합니다. 시즌 종료 후 어느 경로가 얼마나 쓰였고 얼마나 정확했는지 셀 수 있어야 합니다. 특정 블로거에 대한 의존이 다시 높아지는지를 이 수치로 감시하고, 나빠지면 그때 탐색 순서를 조정합니다.

사이트맵 자체는 저장하지 않습니다. 새 글이 계속 올라와 재실행하면 달라지는 상태이기 때문입니다. 한 번 실행하는 동안에만 재사용해 요청 수를 5건으로 유지합니다.

로봇 규칙과 요청 간격은 기존 수집 경로와 동일하게 지킵니다.

⚙️ 작업 내용
---

- 사이트맵 수집과 엄격 매칭 추가
- 탐색 순서를 시드 → 사이트맵 → 웹 검색으로 재구성하고 웹 검색을 지연 호출로 전환
- 출처 표기에 사이트맵 경로 추가
- 위 동작에 대한 테스트 작성

✅ 검증 방법
---

테스트는 네트워크 호출 없이 돌아야 합니다.

성공 기준입니다.

1. 기존 테스트 95개와 신규 테스트가 모두 통과
2. 엄격 매칭이 정식 표기만 잡고 다른 캠퍼스 글과 유사 명칭을 걸러냄
3. 사이트맵으로 출처를 확보한 대학에서는 웹 검색이 호출되지 않음
4. 사이트맵 후보가 모두 실패하면 웹 검색으로 넘어감
5. 캐시를 비우고 일부 대학만 실제 실행했을 때 출처 표기가 사이트맵인 행이 나오고, 그 행의 출처 주소가 해당 대학의 해당 연도 글임을 확인
