# 🚀 [기능요청] 연도별 출력 분리와 아티스트 정규화 보존

📝 현재 문제점
---

두 가지 데이터 손실이 있습니다.

첫째, 크롤러를 다시 실행하면 아티스트 표기 정규화 결과가 사라집니다. 정규화는 수 분이 걸리는 LLM 작업인데, 크롤 재실행 한 번으로 라인업 219행 중 107행의 정식 표기가 원문으로 되돌아갑니다. 캐시에는 원문 표기만 남기 때문에 복원되지 않습니다. 경고도 에러도 없이 조용히 사라집니다.

이것이 실사용에서 계속 터지는 이유는 검수 페이지 때문입니다. 대학 한 곳만 다시 돌리는 버튼도 크롤 전체를 실행하므로, 한 곳을 고칠 때마다 29곳의 정규화가 전부 날아갑니다.

아티스트 마스터 파일이 이 정보를 대신하지 못하는 것도 확인했습니다. 마스터의 별칭 목록으로 표기를 되돌리려 하면 219행 중 61행이 복원되지 않습니다. 원문 표기가 별칭에 들어 있지 않은 경우가 많기 때문입니다. 정규화 결과는 지금 만들어지고 곧바로 버려지는 유일본입니다.

둘째, 산출물이 연도 구분 없이 한 곳에 쌓입니다. 캐시도 결과 파일도 대학당 하나뿐이라, 시드의 연도를 다음 시즌으로 바꾸면 이전 연도가 덮어써지고 다시 볼 방법이 없습니다.

🛠️ 해결 방안 / 제안 기능
---

산출물을 연도별로 분리해 이전 연도가 덮어써지지 않게 합니다. 시드 파일도 연도별로 나눠 지난 시즌의 시드가 동결되게 합니다.

아티스트 정규화 결과는 별도로 보존하고, 크롤이 결과를 만들 때 그것을 다시 반영합니다. 이렇게 하면 크롤을 몇 번 다시 돌리든 정규화가 유지되고, 실행 순서에 대한 의존이 사라집니다.

정규화 결과는 연도와 무관하므로 연도 폴더 바깥에 두고 시즌 사이에 누적합니다. 다음 시즌에는 새로 등장한 아티스트만 정규화하면 되므로, 매년 수 분짜리 작업을 처음부터 다시 돌리지 않습니다. 다만 새 표기가 이미 정한 정식 표기에 제대로 붙도록, 정규화 요청에 기존 표기 목록을 함께 전달해야 합니다.

검수 페이지는 어느 연도를 볼지 서버를 띄울 때 정합니다. 화면에는 연도 선택을 붙이지 않습니다. 검수는 이번 시즌 작업이고, 지난 시즌을 볼 일은 드물기 때문입니다.

기존 산출물은 정규화를 다시 돌리지 않고 새 구조로 옮길 수 있습니다. 현재 라인업 파일에서 표기 대응 167건을 복원할 수 있고, 이것이 지금까지 수집된 이름 165건을 전부 덮는 것을 확인했습니다.

⚙️ 작업 내용
---

- 시드 파일과 산출물 폴더를 연도별로 분리하고, 연도를 지정하는 실행 인자 도입
- 아티스트 정규화 결과를 연도 공통 영역에 보존하고 크롤 결과에 다시 반영
- 정규화 대상을 새로 등장한 아티스트로 한정
- 검수 페이지가 볼 연도를 서버 시작 시점에 지정
- 기존 산출물을 새 구조로 이전
- 위 동작에 대한 테스트 작성

설계 상세는 `docs/specs/20260806_연도별_출력_분리_및_정규화_보존.md`에 있습니다.

✅ 검증 방법
---

성공 기준입니다.

1. 기존 테스트 112개와 신규 테스트가 모두 통과
2. 정규화를 채운 뒤 크롤을 다시 실행해도 정식 표기가 유지됨
3. 지정한 연도의 실행이 다른 연도 폴더를 건드리지 않음
4. 실행 인자의 연도와 시드 파일의 연도가 다르면 즉시 중단됨
5. 정규화 요청에 이미 처리된 표기가 포함되지 않음
6. 기존 산출물을 이전한 뒤, 정규화를 다시 돌리지 않고도 라인업의 정식 표기가 그대로 남아 있음

범위 밖으로 남기는 것이 하나 있습니다. 일부만 처리하는 실행 옵션이 결과 파일을 그만큼만 남기고 나머지 대학 행을 지우는 문제입니다. 이번 변경으로 해결되지 않지만, 스모크 전용 옵션이고 캐시가 남아 전체 재실행으로 복구되므로 별도로 다룹니다.
