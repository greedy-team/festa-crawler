# 산출물을 백엔드 업로드 명세로 전환

### 📌 작업 개요

크롤러 산출 CSV 3종을 백엔드 어드민의 크롤링 번들 업로드 API(`POST /admin/imports/bundle`)
명세에 맞춰 전환. 컬럼 구성·값 형식을 명세와 일치시키고, 명세가 요구하지만 수집하지 않던
필드(축제 소개, 해시태그, 이미지 목록, 입장·티켓 분류, 라인업 일차·순서, 아티스트 장르)를
추출 단계까지 거슬러 올라가 채웠다. 기존 2026년 수집분 29곳은 전체 재크롤로 재생성했다.

### 🎯 구현 목표

- 검토를 마친 `output/<연도>/` 파일을 그대로 업로드할 수 있게 한다
- 내부 스키마와 업로드 스키마를 한 벌로 유지한다 (변환 단계를 두지 않는다)
- 재크롤이 기존 아티스트 정규화 결과를 파괴하지 않는다

### ✅ 구현 내용

#### 추출 스키마 재편

- **파일**: `schema.py`
- **변경 내용**: `ExtractionResult`에서 `outsider_admission`·`ticket_info` 제거,
  `description`·`hashtags`·`external_visitor_policy`·`verification_method`·`ticket_type`·
  `ticket_open_at`·`admission_raw` 추가. 열거값은 `Literal`로 선언. `LineupItem`은
  `day_label`·`date`·`time`을 `day: int | None`으로 대체. `ArtistMaster`는
  `name`·`other_names`·`genre`·`needs_review`로 재편
- **이유**: 열거값을 `Literal`로 두면 pydantic이 검증하므로, LLM이 규격 밖 값을 내면
  기존 재시도 경로가 그대로 걸린다. 별도 검증 코드가 필요 없다

#### 본문 이미지 수집

- **파일**: `fetch.py`
- **변경 내용**: `parse_html`이 본문 컨테이너 안의 `<img>`를 절대 URL로 수집(중복 제거,
  최대 5장). `FetchResult.image_urls` 추가
- **이유**: 명세의 `image_urls`(히어로·캐러셀용)를 채우기 위함. 기존 `og:image` 1장은
  `poster_url`로 그대로 쓴다

#### 추출 프롬프트 확장

- **파일**: `extract.py`
- **변경 내용**: 축제명에서 주최명 제외, 소개문 2~3문장 생성, 해시태그는 본문에 있는 것만,
  입장·티켓 열거값은 근거가 있을 때만, `admission_raw`는 판단 근거 원문 인용, `day`는
  정수 판단 규칙을 추가
- **이유**: "본문에 없으면 null" 원칙은 유지하고 새 필드에도 같은 규칙을 적용

#### 산출 CSV 컬럼 전환

- **파일**: `crawl.py`
- **변경 내용**: `FESTIVAL_FIELDS`(19열)·`LINEUP_FIELDS`(6열)를 명세 헤더로 교체.
  `festival_id()`를 `import_key()`로 개명(값 형식은 동일). CSV 경계에서 열거값 대문자화,
  다중값 `|` 조인, 인스타 핸들→URL 변환, `admission_raw` 200자 컷, 일차별 `order` 부여,
  `is_secret`→`revealed` 반전
- **이유**: 내부 상태는 소문자로 두고 대문자 변환을 CSV 경계 한 곳에만 두면, 캐시·재실행
  로직이 표기 변경에 영향받지 않는다

#### 캐시 스키마 버전과 재수집 폴백

- **파일**: `crawl.py`
- **변경 내용**: 캐시 레코드에 `schema_version: 2` 기록. 버전이 다른 캐시는 자동 재수집.
  재수집이 실패했는데 구 캐시가 성공 상태이고 **시드 `url`·`year`가 그대로면** 구 결과를
  반환하고 캐시 파일은 건드리지 않는다
- **이유**: 스키마 전환에 필요한 재수집을 자동화하면서, 원본 글이 삭제된 대학의 멀쩡한
  기존 데이터를 잃지 않기 위함

#### 아티스트 마스터 전환과 1회성 마이그레이션

- **파일**: `enrich.py`, `schema.py`
- **변경 내용**: `ARTIST_FIELDS`를 `name,other_names,genre,image_url,needs_review`로 교체.
  정규화 프롬프트에 장르 분류 규칙 추가. 구 스키마 `artists.csv`를 감지해 기계적으로
  변환하고, 기존 아티스트의 장르는 LLM 1콜로 분류
- **이유**: 별칭·영문 표기·본명이 명세에서 `other_names` 하나로 합쳐지므로 기존 파일도
  같은 형태로 옮겨야 한다. 비싼 정규화 결과(`artist_mapping.json`)는 건드리지 않는다

#### 검수 화면 갱신

- **파일**: `review.html`
- **변경 내용**: 새 컬럼명으로 교체. 상세에 소개·해시태그·이미지·입장 분류·판단 근거 표시.
  라인업은 `N일차 · M번` 표기, `revealed=false`에 자물쇠 표시
- **이유**: `serve.py`는 CSV를 그대로 넘기므로 화면만 바꾸면 된다

### 🧭 결정 기록 (ADR)

#### 내부 스키마와 업로드 스키마를 한 벌로 유지 (제자리 전환)

- **문제**: 산출물을 명세에 맞추는 방법이 두 가지였다 — 내부 형식을 유지하고 업로드 직전에
  변환하거나, 산출물 자체를 명세 형식으로 바꾸거나
- **선택**: 산출물 자체를 명세 형식으로 전환. 별도 변환 단계를 두지 않는다
- **대안**:
  - export 스크립트 추가 — 신규 필드가 추출 단계까지 거슬러 올라가므로 어차피 파이프라인
    전체를 손대야 하고, 스키마 두 벌은 반드시 어긋난다
- **트레이드오프**: 백엔드 명세가 바뀌면 크롤러 전 단계가 따라 움직인다. 대신 "검토한 파일을
  그대로 올린다"가 성립한다
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### `flag != OK`인 축제의 라인업 행은 출력하지 않는다

- **문제**: 수집에 실패했어도 추출 결과가 일부 남은 축제가 있다. 그 라인업을 CSV에 낼지
- **선택**: 축제가 `OK`가 아니면 라인업 행을 만들지 않는다
- **대안**:
  - 그대로 출력 — 백엔드에서 연결 대상 축제를 못 찾아 전부 `INVALID`가 된다. 검수자가
    처리할 수 없는 오류 행만 늘어난다
- **트레이드오프**: 실패한 축제의 라인업 정보는 CSV에서 볼 수 없다. `raw/` 캐시에는 남는다
- ⭐ **볼트 승격 권장** — `/capture`로 `knowledge/decisions/`에 등록

#### 아티스트 분류를 `genre` 하나로 일원화하고 `category`를 제거

- **문제**: 명세에 열거값 `genre`와 자유텍스트 `category`가 함께 있었다
- **선택**: `category`를 산출물에서 제거하고 `genre`만 채운다. 백엔드에도 명세에서
  제거를 제안한다
- **대안**:
  - 둘 다 유지 — 크롤러가 자유텍스트 분류를 채울 근거가 없어 항상 비게 된다
- **트레이드오프**: "가수 · 싱어송라이터" 같은 세분 표기가 필요해지면 명세를 되돌려야 한다
- ⭐ **볼트 승격 권장** — 외부 계약(백엔드 명세) 변경 요청이다

#### 캐시 버전 불일치는 자동 재수집, 재수집 실패는 구 결과 유지

- **문제**: 스키마가 바뀌어 구 캐시를 못 쓰게 됐다. 중단하고 안내할지, 자동 재수집할지
- **선택**: 버전이 다르면 그 대학만 자동 재수집한다. 단, 재수집이 실패했고 구 캐시가 성공
  상태이며 **시드 `url`·`year`가 그대로일 때만** 구 결과를 반환하고 캐시 파일도 지우지 않는다
- **대안**:
  - 감지 후 중단하고 마이그레이션 안내 — 연도 폴더 도입 때는 이 방식을 썼다. 이번에는
    재수집이 의도된 동작이고 대학별 진행 로그가 이미 보여 안내가 불필요하다
  - 무조건 재수집 결과로 덮기 — 원본 글이 삭제된 대학의 기존 데이터를 잃는다
  - 캐시가 어긋난 모든 경우에 폴백 — 시드 URL을 고쳤는데 새 URL이 실패하면 그 수정이
    조용히 무시되고, `OK` 행이라 검수 화면의 기본 필터에도 안 잡힌다. 그래서 폴백 조건을
    "버전만 다른 경우"로 좁혔다
- **트레이드오프**: 폴백이 걸린 행은 신규 필드가 빈 채로 남는다. 로그에 표시된다
- ⭐ **볼트 승격 권장** — 재실행 안전성에 관한 결정이다

#### 라인업 `order`는 본문 등장 순서로 부여

- **문제**: 명세의 `order`는 "헤드라이너가 1"이다. 크롤러가 헤드라이너를 판정할지
- **선택**: 일차 안에서 본문에 등장한 순서대로 1부터 매긴다. 헤드라이너 판정은 하지 않는다
- **대안**:
  - LLM이 본문 표기로 재배열 — 추출 규칙과 검증이 복잡해지고, 검수자가 어느 쪽이 판단한
    값인지 구분할 수 없다
- **트레이드오프**: 검수자가 순서를 손봐야 하는 경우가 생긴다
- 기존 "수집 모듈은 판단하지 않는다"를 그대로 따른 것이라 별도 승격은 불필요

### 🔧 주요 변경사항 상세

#### `build_lineup_rows` — 일차별 순서와 시크릿 게스트

일차별 카운터로 `order`를 1부터 매긴다. `day`가 비어 있는 항목끼리도 하나의 그룹으로
묶여 번호가 이어진다. 시크릿 게스트는 `revealed=false`로 두고 `artist_raw`·
`artist_canonical`을 빈 값으로 낸다 — 명세의 검증 규칙이 그렇게 요구한다.

#### `_keep_stale_on_failure` — 폴백 지점

재수집 실패는 두 곳에서 끝난다. 탐색 자체가 실패한 조기 반환과, 모든 후보가 검증을
통과하지 못한 정상 종료다. 두 지점 모두 이 함수를 지나므로 어느 쪽으로 실패해도 구
결과가 유지된다.

**특이사항**:
- 폴백이 발동하면 캐시 파일을 다시 쓰지 않는다. 다음 실행에서 다시 재수집을 시도한다
- 내부 레코드의 `flag`·`discovery`는 소문자로 유지된다. CSV로 나갈 때만 대문자가 된다

#### `_migrate_artists_csv` — 구 파일 변환

헤더가 구 6열이면 변환하고, 아니면 아무것도 하지 않는다. `name_en`·`real_name`·`aliases`를
순서를 지키며 중복 제거해 `other_names`로 합치고, 대표명과 같은 표기는 제외한다.
장르 분류 호출이 실패하면 파일을 건드리지 않으므로 다음 실행에서 다시 시도된다.

### 📌 참고사항

**백엔드에 전달할 사항**

- `flag` 전체 7종: `OK` `NO_CANDIDATE` `FETCH_FAILED` `EMPTY_BODY` `EXTRACT_FAILED`
  `MISMATCH` `NO_SOURCE` — 명세의 미완성 표를 채우는 값이다
- `artists.csv`에서 `category` 제거, `needs_review` 추가를 제안한다
- 산출물 인코딩은 BOM 붙은 UTF-8이다. 업로드 파서가 허용하는지 확인이 필요하다
- `flag != OK`인 행은 `discovery`가 빈 값이다. 필수 컬럼이지만 해당 행은 어차피 `SKIP`된다
- 명세 문서 오탈자: festivals 헤더 코드블록에 `instagram_url` 누락, artists 헤더 끝의
  불필요한 구분자, 파이프 문자가 표 마크다운을 깨뜨리는 곳

**알려진 한계**

- `hashtags`가 26행 중 3행에서만 채워졌다. 티스토리는 태그를 본문 컨테이너 바깥에 두는
  구조여서 본문 추출에 잡히지 않는 것으로 보인다. 필요해지면 태그 영역을 따로 수집한다
- 입장·티켓 열거값이 낮은 것은 원문에 해당 정보가 없기 때문이다. 채워진 행에는
  `admission_raw`에 판단 근거 원문이 함께 들어 있어 검수자가 대조할 수 있다
- 축제 1건(건국대)은 `OK`이면서 `name`이 비어 있다. 원문에 축제명 표기가 없어 추측하지
  않은 결과다. 명세상 `name`은 필수이므로 업로드 시 `INVALID`로 잡히고 검수자가 채운다
