### 📌 작업 개요

크롤러를 다시 실행하면 아티스트 표기 정규화가 조용히 사라지던 문제를 고쳤습니다. 정규화 결과를 `output/artist_mapping.json`에 영속화하고 `crawl.py`가 매 실행마다 그것으로 `artist_canonical`을 채우게 해, 재실행이 정규화를 지우는 대신 복원하도록 바꿨습니다. 함께 산출물을 연도별 폴더로 나눠 이전 연도가 덮어써지지 않게 했습니다.

**보고서 파일**: `docs/reports/20260808_14_연도별_출력_분리와_정규화_보존.md`

### 🔍 문제 분석

두 가지 손실이 있었습니다.

**1. crawl 재실행이 enrich 결과를 지웠습니다.**

`enrich.py`가 `lineup.csv`의 `artist_canonical`에 정규화 값을 쓰는데, `crawl.py`가 `lineup.csv`를 매번 처음부터 만들면서 `artist_canonical = artist_raw`로 되돌렸습니다. 캐시(`output/raw/*.json`)에는 원문 표기만 있어 복원되지도 않았습니다.

```
lineup.csv 219행 중 107행이 정규화된 상태
→ crawl.py 재실행 1회로 107행 전부 원문으로 리셋
```

에러도 경고도 없었습니다. 정규화는 LLM 호출 1건에 실측 578초가 드는 작업입니다.

실사용에서 계속 터진 이유는 검수 페이지입니다. 대학 1곳만 다시 돌리는 버튼도 crawl 전체를 실행하므로(DEC-0021), 한 곳을 고칠 때마다 29곳의 정규화가 전부 날아갔습니다.

아티스트 마스터가 이 정보를 대신하지 못하는 것도 실측으로 확인했습니다. `artists.csv`의 `aliases`를 역인덱스해 복원을 시도하면 219행 중 **61행이 실패**합니다 — `트리플에스(tripleS)` 같은 원문 표기가 aliases에 들어 있지 않기 때문입니다. `enrich`가 만드는 매핑이 유일본이었고, 쓰이고 곧바로 버려졌습니다.

**2. 연도가 바뀌면 이전 연도가 덮어써졌습니다.**

`output/raw/`는 대학당 JSON 1개, CSV도 대학당 1행이었습니다. 시드의 `year`를 바꾸면 캐시가 무효화되고 이전 연도 데이터가 사라졌습니다.

### 🎯 구현 목표

- 연도별 산출물이 서로를 덮지 않는다
- crawl을 몇 번 다시 돌리든 `artist_canonical`이 유지된다
- 다음 시즌 정규화가 이미 정한 표기를 재사용한다 (매년 578초를 다시 쓰지 않는다)

### ✅ 구현 내용

#### 정규화 매핑 영속화

- **파일**: `crawl.py`
- **변경 내용**: `ARTIST_MAPPING_NAME`, `load_artist_mapping(base_dir)`, `save_artist_mapping(base_dir, mapping)` 추가. `write_csv`와 같은 임시 파일 + `os.replace()` 방식으로 원자적으로 씁니다
- **이유**: 정규화 결과의 유일본을 산출물 밖에 두어야 재생성이 그것을 파괴하지 않습니다

#### crawl이 매핑을 적용

- **파일**: `crawl.py`
- **변경 내용**: `build_lineup_rows(record, mapping)`가 `mapping.get(artist_raw, artist_raw)`로 `artist_canonical`을 채웁니다. `mapping`은 기본값 없는 필수 인자입니다
- **이유**: 기본값을 두면 빠뜨렸을 때 조용히 원래 증상으로 돌아갑니다. 그 조용한 누락이 이 이슈의 증상 자체였습니다

#### 연도별 시드와 출력 폴더

- **파일**: `crawl.py`, `universities.csv` → `universities-2026.csv`
- **변경 내용**: `run(year, base_dir, limit)`이 `universities-<연도>.csv`를 읽어 `output/<연도>/`에 씁니다. `--input`·`--output-dir` 제거, `--year` 필수. 시드의 `year` 컬럼이 `--year`와 다르면 중단합니다
- **이유**: 경로를 따로 받으면 연도가 어긋난 조합이 가능해집니다. 손잡이를 하나로 줄이면 그 조합 자체가 성립하지 않습니다

#### enrich를 연도 공통 + 증분으로

- **파일**: `enrich.py`
- **변경 내용**: `year_dirs()`로 전 연도의 `raw/`를 훑고, 매핑 키에 없는 이름만 LLM에 보냅니다. 프롬프트에 기존 정식 표기 목록을 함께 싣고(`KNOWN_BLOCK_TEMPLATE`), 매핑과 `artists.csv`를 연도 공통으로 누적합니다
- **이유**: 아티스트 표기는 연도와 무관합니다. 매년 전량 재정규화하면 578초를 시즌마다 다시 씁니다

#### 응답 수용 범위 제한

- **파일**: `enrich.py`
- **변경 내용**: `mapping.update()`가 이번 배치에서 실제로 물어본 이름의 매핑만 받습니다
- **이유**: 프롬프트에 기존 표기를 보여주게 되면서 모델이 그 키를 응답에 되돌려줄 수 있게 됐고, 되돌아온 값이 다르면 확정된 표기가 덮였습니다. 그 이름은 다시 LLM에 가지 않으므로 영구적이었습니다

#### 옛 레이아웃 감지 가드

- **파일**: `crawl.py`
- **변경 내용**: `run()` 초입에서 `output/festivals.csv`가 있으면 마이그레이션 절차와 함께 중단합니다. `out_dir.mkdir()`보다 먼저 검사합니다
- **이유**: 옛 레이아웃으로 실행하면 캐시를 못 찾아 29곳을 조용히 재수집합니다(30~50분 + 세션 한도). 실패로 보이지 않는 실패입니다

#### 검수 페이지 연도 지정

- **파일**: `serve.py`, `admin.sh`
- **변경 내용**: `--year`를 필수로 받아 `OUT_DIR`과 허용 목록 시드를 유도하고, crawl 서브프로세스에 `--year`를 전달합니다. `Job.start`가 문자열 대신 `list[str]`을 받습니다. `load_data(out_dir, base_dir)`가 `artists.csv`만 연도 공통 경로에서 읽습니다
- **이유**: 검수는 이번 시즌 작업이라 연도를 서버 시작 시 고정하는 것으로 충분합니다. `review.html`은 손대지 않았습니다

### 🔧 주요 변경사항 상세

#### `output/` 레이아웃

```
output/
  artists.csv           연도 공통 마스터 (122행)
  artist_mapping.json   연도 공통 매핑 (167건)
  2026/
    festivals.csv  lineup.csv  raw/  discovered/
```

연도 공통과 연도별을 가르는 기준은 연도 의존성입니다. 축제와 라인업은 그 해의 사실이고, 아티스트 표기는 아닙니다.

**특이사항**: 이 판단을 한 번 놓쳐 `serve.load_data`가 `output/<연도>/artists.csv`를 읽었고, 파일이 없으면 `read_csv`가 빈 목록을 반환하는 탓에 아티스트 표가 **오류 없이 비었습니다**. 헤드리스 확인에서 `artists: 0`으로 드러났습니다.

#### `enrich.py`의 실행 흐름

```
전 연도 raw/*.json → 이름 수집
  → 매핑 키에 있는 이름 제외, 새 이름만 LLM에 전달 (기존 정식 표기 목록 동봉)
  → 응답 중 물어본 이름의 매핑만 수용해 병합·저장
  → 모든 연도 폴더의 lineup.csv를 매핑에 맞춰 갱신
```

마지막 단계는 **신규 아티스트가 없어도 돕니다.** LLM 호출만 건너뛰고 CSV 갱신은 항상 실행합니다.

**특이사항**: 이 무조건 갱신이 매핑을 손으로 고쳤을 때의 유일한 반영 경로입니다. `needs_review` 아티스트를 교정하려면 `artist_mapping.json`을 고치고 `enrich.py`를 다시 돌리면 되며, LLM 호출 없이 전 연도에 반영됩니다.

#### 기존 데이터 마이그레이션

LLM 재실행 없이 이전했습니다. 당시 `lineup.csv`에서 `{artist_raw: artist_canonical}` 167건을 복원할 수 있었고, `collect_raw_names`가 찾는 165건을 전부 덮었습니다(미커버 0).

```
1. mkdir output/2026
   mv output/{festivals.csv,lineup.csv,raw,discovered} output/2026/
2. output/2026/lineup.csv 에서 artist_mapping.json 생성
3. output/artists.csv 는 output/ 에 그대로
```

`output/`은 gitignore 대상이라 커밋되지 않습니다.

### 🧪 테스트 및 검증

단위 테스트 **138개 통과**(기존 112 + 신규 26). 네트워크와 LLM 호출은 전부 monkeypatch했습니다.

| 대상 | 확인 |
| --- | --- |
| 재실행 보존 | 매핑을 채운 뒤 `run()`을 두 번 호출해도 정식 표기 유지. 되돌리면 실패하는 것까지 확인 |
| enrich → crawl 종단 | `enrich` 실행 후 `crawl.run()`을 돌려도 정규화가 남는지 |
| 응답 범위 제한 | 응답이 기존 키를 다시 매핑해도 확정 표기가 유지되는지 |
| 증분 정규화 | 매핑에 있는 이름은 프롬프트에 들어가지 않고, 기존 정식 표기는 전달되는지 |
| 연도 격리 | `--year 2026` 실행이 `output/2027/`을 건드리지 않는지 |
| 시드 검증 | `--year`와 시드 `year` 컬럼 불일치 시 중단 |
| 옛 레이아웃 가드 | 평면 레이아웃에서 중단하고, 새 클론·정상 레이아웃에서는 발동하지 않는지 |
| 매핑 파일 | 없으면 빈 매핑, 깨졌거나 값이 문자열이 아니면 중단 |
| 경로 분리 | `artists.csv`를 `base_dir`에서 읽는지. `out_dir.parent`로 우회하면 실패하도록 구성 |

**종단 검증** (실데이터):

```
이전 전:              lineup 219행 / 정규화 107행
crawl.py --year 2026: lineup 219행 / 정규화 107행    ← 캐시 히트, 수집 호출 없음
enrich.py:            "새 아티스트 없음 — 정규화 건너뜀 (매핑 167건)"  5초 미만
GET /api/data:        festivals 29 · lineup 219 · artists 122
```

`raw/`·`discovered/` 캐시 파일의 수정 시각이 재실행일과 다른 것으로 캐시 전용 실행임을 확인했습니다.

**브라우저 수동 점검은 미완료입니다** — 화면이 의도대로 보이는지는 사람이 직접 확인해야 합니다.

### 📌 참고사항

- **`artist_mapping.json`의 저장 위치가 미결입니다.** 수 분짜리 정규화의 유일본인데 gitignore된 `output/` 안에 있어 `rm -rf output/`이면 복구할 수 없습니다. 저장소가 공개라 커밋은 노출을 뜻하므로, 루트로 옮기되 gitignore를 유지하는 선택지가 있습니다
- **`needs_review: true` 아티스트 33명은 자동 재시도되지 않습니다.** 교정 경로는 README에 기재했습니다
- **다음 시즌 시작 시 `universities-<연도>.csv`의 `url` 컬럼을 비우세요.** 시드 URL 21개 중 19개가 주소에 연도가 박힌 글이라, 비우지 않으면 죽은 URL을 전부 수집하고 추출까지 호출한 뒤에야 검증에서 떨어집니다 (이슈 #11 보고서)
- **범위 밖:** `--limit N`이 CSV를 N행으로 잘라내는 문제는 이번 변경으로 해결되지 않습니다. 다만 복구는 싸졌습니다 — 전체 재실행이 잘린 행과 그 정규화를 함께 되살립니다
