### 📌 작업 개요

수동 URL이 없거나 실패한 대학을 웹 검색으로 찾은 후보 URL로 채우는 탐색 단계 추가.
크롤링 대상 21곳 중 14곳(67%)이 단일 블로거 `memogipost.tistory.com` 한 명에게 의존하던
구조를 벗어나는 것이 목적.

실행 결과 URL이 없던 8곳이 0곳으로 줄고 `ok`가 20곳에서 26곳으로 증가.

### 🎯 구현 목표

- 수동 큐레이션 URL을 유지하되, 비어 있거나 실패한 대학만 검색으로 보완
- 검색이 지저분한 후보를 주더라도 잘못된 출처가 채택되지 않도록 기존 검증 장치 재사용
- 발행 판단은 사람이 유지 (파이프라인 문서 5.1 불변)

### ✅ 구현 내용

#### 후보 URL 탐색 모듈 신규

- **파일**: `discover.py`
- **변경 내용**: `claude --tools "WebSearch"`로 대학명·연도를 검색해 후보 URL 목록 반환.
  `discover()`가 검색·파싱·차단 도메인 필터를, `discover_cached()`가 캐시를 담당
- **이유**: `fetch.py`와 같은 원칙으로 **후보를 모으기만 하고 판단하지 않는다.**
  "이 글이 맞는 글인가"는 기존 `verify()`가 판정하므로 관심사가 겹치지 않음

#### 탐색 분기와 후보 폴백

- **파일**: `crawl.py`
- **변경 내용**: `process_row`가 수동 URL을 먼저 시도하고, 없거나 실패하면 후보를 최대 3개까지
  순차 시도해 `verify`를 통과한 첫 후보를 채택. URL 1건 처리 로직은 `_attempt_url`로 분리
- **이유**: 검증된 수동 URL을 버리지 않으면서 호출량도 최소화. 실제 탐색 대상은 29곳이 아니라
  9곳 수준

#### LLM 도구 제어

- **파일**: `extract.py`
- **변경 내용**: `call_claude`에 `tools` 인자 추가 (기본값 `""`). 탐색 호출만 `"WebSearch"`로 켬
- **이유**: LLM 접점을 `call_claude` 하나로 유지하면서 도구 노출을 탐색으로 한정.
  신뢰할 수 없는 블로그 본문을 읽는 추출·정규화 호출은 도구 전면 차단 상태 유지

#### 출처 추적 컬럼과 신규 flag

- **파일**: `crawl.py`, `schema.py`
- **변경 내용**: `festivals.csv`에 `discovery` 컬럼(`manual`/`search`) 추가, `no_candidate` flag 신설
- **이유**: 시즌 종료 후 "검색으로 찾은 것과 수동으로 넣은 것 중 어느 쪽이 정확했나"를 세는 근거.
  `no_source`(출처 확보 실패)와 `no_candidate`(탐색했으나 후보 없음)를 구분해야 검색 실패를 추적 가능

#### 운영 문서 갱신

- **파일**: `README.md`
- **변경 내용**: 파이프라인·정보구조·모듈 다이어그램(mermaid 4종) 추가, flag 표와 캐시 설명 갱신
- **이유**: `no_candidate`·`discovery`가 표에 없었고, 캐시 키가 시드 URL 기준으로 바뀐 것과
  `extract_failed` 미캐시가 반영되지 않아 운영자가 CSV를 검수할 때 참조할 곳이 없었음

### 🧭 결정 기록 (ADR)

#### 검색 수단으로 `claude` CLI의 WebSearch 도구 채택

- **문제**: 대학명×연도로 후보 URL을 찾을 검색 수단이 필요
- **선택**: `claude --tools "WebSearch"` — 기존 구독으로 동작, 별도 키 불필요
- **대안**:
  - Google Custom Search JSON API — 신규 고객 사용 불가, 2027-01 서비스 종료
  - 네이버 검색 API — 개발자센터 앱 등록의 '사용 API' 목록에 검색이 없음
  - 검색 결과 페이지 스크래핑 — `google.com/robots.txt`는 `Disallow: /search`,
    `search.naver.com`은 전체 `Disallow: /`. 스펙 §8 준수 사항과 정면 충돌
- **트레이드오프**: 검색 1건에 60초 이상. 29곳 전체 실행이 30~50분으로 늘고 세션 한도 리스크 증가
- ⭐ **볼트 승격 권장** — 외부 서비스 가용성에 기반한 결정이라 나중에 "왜 검색 API를 안 썼나"가 나옴

#### 탐색 모듈은 판단하지 않는다

- **문제**: LLM이 URL을 지어낼 수 있고, 검색 결과에 무관한 글이 섞임
- **선택**: `discover.py`는 후보 수집과 정책 필터(차단 도메인)만. 관련성 판정은 기존 `verify()`에 위임
- **대안**:
  - 탐색 단계에서 관련성 점수를 매겨 거르기 — 판정 로직이 두 곳에 생겨 기준이 어긋남
  - 후보를 사람이 고르게 하기 — 반자동 목표에 어긋나고 검수 부담 증가
- **트레이드오프**: 무관한 후보에도 추출 비용을 쓴다. 다만 `verify` 실패는 다음 후보로 넘어가므로
  최대 3회로 제한됨
- **결과**: 환각 방어를 새로 만들 필요가 없어짐. 지어낸 URL은 `fetch_failed`, 엉뚱한 글은 `mismatch`
- ⭐ **볼트 승격 권장** — 다른 수집 소스를 붙일 때도 그대로 적용되는 경계 원칙

#### 캐시 키를 시드 URL(`seed_url`) 기준으로 변경

- **문제**: 탐색으로 성공하면 실제 사용한 `url`이 시드와 달라져, `url`로 캐시를 판정하면 매 실행마다
  캐시가 빗나가 60초짜리 검색을 다시 돌게 됨
- **선택**: 시드의 URL을 `seed_url`로 따로 저장하고 그것과 `year`로 캐시 유효성 판정
- **대안**: 탐색 결과를 `universities.csv`에 역기록 — 사람이 관리하는 시드 파일을 코드가 덮어쓰게 됨
- **트레이드오프**: 기존 캐시 파일에 `seed_url`이 없어 도입 시 전체 재처리 1회 필요

#### 상위 후보 1개만 추출하고 교차 검증은 보류

- **문제**: 한 대학에 후보가 여러 개 나오는데 몇 개까지 추출할지가 비용과 정확도를 동시에 가름
- **선택**: `verify`를 통과한 첫 후보만 채택 (최대 3개까지 시도)
- **대안**: 상위 3개를 모두 추출해 교차 검증 — 정확도는 높지만 LLM 호출이 3배라 세션 한도에 걸림
- **트레이드오프**: 파이프라인 문서 4.3의 신뢰도 산정을 아직 못 씀. 다만 탐색이 대학당 후보를
  여러 개 만들어내므로 나중에 켤 수 있는 상태는 됨

### 🔧 주요 변경사항 상세

#### `discover.py`

`BLOCKED_DOMAINS`는 나무위키(CC BY-NC-SA 비영리 라이선스)와 검색 엔진 결과 페이지를 제외한다.
`_is_blocked`는 userinfo와 포트를 떼고 접미사 매칭을 하므로 `m.search.naver.com`·`namu.wiki:443`도
막히고, `notnamu.wiki` 같은 유사 도메인은 통과한다.

`discover_cached`의 반환 타입이 `list[str] | None`인 것이 중요하다. **`None`은 "탐색 자체가
실패했으니 캐시하지 말라"는 신호**이고, 빈 리스트는 "검색은 됐는데 후보가 정말 0건"이다.
호출부가 이 둘을 구분하지 못하면 세션 한도 같은 일시적 실패가 캐시에 굳어 재시도가 영영 막힌다.

**특이사항**:
- 탐색 프롬프트는 최상위 **객체** `{"candidates": [...]}`를 요구한다. 배열 `[...]`로 오면
  기존 `_extract_json`이 `{`~`}` 구간만 잘라내므로 파싱에 실패한다
- 탐색 타임아웃은 300초 (추출용 120초와 별개). 실측 63초 + 검색 왕복 여유

#### `crawl.py`의 flag 결정

네 갈래로 나뉜다.

| 상황 | flag | discovery |
|---|---|---|
| 수동 URL 성공 | `ok` | `manual` |
| 후보 중 하나 성공 | `ok` | `search` |
| 전부 실패 + 수동 URL 있었음 | 수동 시도의 실패 flag 유지 | 빈칸 |
| 전부 실패 + 수동 URL 없었음 | `no_candidate` | 빈칸 |

세 번째 경우에 `no_candidate`로 덮지 않는 이유는 "URL이 깨졌다"는 정보가 더 쓸모 있기 때문이다.

### 📌 참고사항

- **탐색 출처가 기관 쪽으로 분산된 것이 이번 작업의 핵심 성과다.** 개인 블로거는 그만두면
  사라지지만 대학 공식 홈페이지와 학보사는 매년 존재한다
- `discovery=search`인 행은 손으로 고른 출처가 아니므로 검수 시 우선 확인한다. 대학 공식
  홈페이지나 학보사면 신뢰도가 높고, 커뮤니티·티켓 플랫폼이면 한 번 더 본다
- 탐색 성공 6곳 중 3곳은 라인업이 0건이다. 원문 자체에 라인업이 없음을 확인했으며 버그가 아니다
- 못 채운 3곳(숙명여대·동덕여대·삼육대) 중 동덕여대·삼육대는 검색 후보가 인스타그램 URL로만
  채워져 실패했다 → 이슈 #5로 분리
