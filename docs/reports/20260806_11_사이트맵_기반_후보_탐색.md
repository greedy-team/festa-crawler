### 📌 작업 개요

후보 URL 탐색에 사이트맵 경로를 추가했습니다. 탐색 순서가 `시드 URL → 사이트맵 → 웹 검색`이 되고, 사이트맵이 출처를 확보하면 웹 검색을 아예 호출하지 않습니다.

탐색이 전적으로 웹 검색에 의존하고 있었습니다. 1건에 60초 이상 걸리고 구독 세션 한도를 소모하는데, 이 한도는 크롤러가 실제로 중단되는 원인입니다.

**보고서 파일**: `docs/reports/20260806_11_사이트맵_기반_후보_탐색.md`

### 🎯 구현 목표

- 이미 출처로 쓰는 블로그의 사이트맵에서 후보 URL을 얻어 웹 검색 호출을 건너뛴다
- 잘못된 출처를 끌어오지 않는 매칭 규칙을 정한다
- 어느 경로로 출처가 확보됐는지 산출물에 남겨 사후에 편중을 측정할 수 있게 한다
- 외부 의존성 추가 없이, 기존 robots·요청 간격 규칙을 그대로 지킨다

### ✅ 구현 내용

#### robots·간격을 지키는 텍스트 수집

- **파일**: `fetch.py`
- **변경 내용**: `fetch_text(url) -> str | None` 추가. 기존 `_robots_allowed`·`_respect_rate_limit`·`USER_AGENT`를 재사용해 응답 본문을 파싱 없이 그대로 반환하고, robots 차단·네트워크 오류·HTTP 오류 시 `None`
- **이유**: 사이트맵은 XML이라 본문 추출 경로(`fetch_body`)가 맞지 않습니다. 네트워크 정책을 `fetch.py` 한 곳에 유지해야 robots·간격 규칙이 두 모듈에서 어긋나지 않습니다

#### 사이트맵 후보 수집

- **파일**: `discover.py`
- **변경 내용**: `SITEMAP_SOURCES`(블로그 5곳) 상수와 `discover_sitemap(university, year) -> list[str]` 추가. `<loc>`를 뽑아 퍼센트 디코딩한 뒤 `/entry/` 포함 · 대학 정식 표기 포함 · 대상 연도 포함 · 차단 도메인 아님을 모두 만족하는 URL만 등장순으로 반환
- **이유**: 티스토리 계열은 글 주소에 제목이 슬러그로 박히므로 주소만으로 대학과 연도를 판별할 수 있습니다. 요청 1건으로 그 블로그의 전체 글을 훑습니다

#### 탐색 순서 재구성과 웹 검색 지연 호출

- **파일**: `crawl.py`
- **변경 내용**: `process_row`에 인라인으로 있던 후보 시도 루프를 `_try_candidates(candidates, row, record, source) -> bool`로 추출하고, 사이트맵 → 웹 검색 순으로 두 번 호출
- **이유**: 두 소스가 같은 루프를 쓰므로 블록을 복사하지 않기 위함입니다. 사이트맵 후보가 검증을 통과하면 `discover_cached`를 호출하지 않아 60초와 세션 한도가 통째로 절약됩니다

#### 테스트 네트워크 차단

- **파일**: `conftest.py`
- **변경 내용**: 모든 테스트에서 `discover._sitemap_urls`를 빈 목록으로 두는 autouse 픽스처 추가
- **이유**: `discover_sitemap`이 생기는 순간 기존 `test_crawl.py`의 탐색 경로 테스트가 실제 사이트맵을 받으러 나갑니다. 사이트맵을 쓰는 테스트만 이 값을 직접 덮어씁니다

#### 검수 화면 필터 수정

- **파일**: `review.html`
- **변경 내용**: `검색출처` 필터가 `discovery`가 `sitemap` 또는 `search`인 행을 모두 보여주도록 수정
- **이유**: README에는 그렇게 갱신해놓고 화면 코드를 고치지 않은 상태였습니다. 사이트맵으로 채택된 행은 `flag=ok`라 `문제만` 필터에도 안 걸리므로, 검수 우선 대상이 `전체` 외 어디에서도 보이지 않았습니다

### 🧭 결정 기록 (ADR)

#### 매칭을 대학 정식 표기 완전 포함으로 한정

- **문제**: 사이트맵 URL에서 대학을 어떻게 식별할 것인가. 느슨하게 잡을수록 커버리지가 오르지만 잘못된 출처가 섞입니다
- **선택**: 대학 정식 표기(`고려대학교`)가 URL에 그대로 들어 있는 것만 후보로 삼습니다. 시드 29곳 중 17곳 커버
- **대안**:
  - 어간 매칭(`고려대`) — 커버리지가 23곳으로 오르지만 추가분 21건 대부분이 다른 캠퍼스입니다(고려대 세종, 한양대 에리카, 건국대 글로컬, 중앙대 다빈치, 연세대 미래). `verify`가 대학명과 연도만 보므로 다른 캠퍼스 글이 그대로 통과합니다
  - 줄임말 매칭(`고대`·`성대`) — 커버리지 증가 0곳에 부분 문자열 충돌만 생깁니다. `성대`가 경성대·한성대를, `연대`가 경연대회를, `한대`가 유한대학교를 잡았습니다. 줄임말로만 실린 시드 대학은 사실상 없고, `이화여대`·`덕성여대`는 정식 표기 글이 따로 있어 이미 잡힙니다
- **트레이드오프**: 12곳은 사이트맵이 못 잡아 웹 검색으로 폴백합니다. 절감 폭을 줄이는 대신 잘못된 캠퍼스 채택 위험을 만들지 않았습니다
- ⭐ **볼트 승격 권장** — 커버리지와 정확도를 맞바꾼 판단이며, 나중에 "왜 23곳을 포기했나"가 나올 결정입니다

#### 사이트맵을 웹 검색 앞에 두되 출처 편중은 사후 측정

- **문제**: 대상 사이트맵 5곳이 전부 개인·소규모 블로그입니다. 앞단에 두면 특정 블로거 의존이 다시 높아질 수 있습니다
- **선택**: 시드 → 사이트맵 → 웹 검색 순으로 두고, `discovery` 컬럼에 `sitemap` 값을 남겨 시즌 종료 후 분포를 셉니다. 수치가 나쁘면 그때 순서를 재조정합니다
- **대안**:
  - 사이트맵을 웹 검색 실패 시에만 — 편중 위험은 없지만 웹 검색을 매번 부르게 되어 절감 목적이 사라집니다
  - 기관 도메인 우선 정렬 — 사이트맵 출처가 전부 블로그라 실질 효과가 없고, 수집 모듈이 관련성을 판정하지 않는다는 기존 구조와 충돌합니다
- **트레이드오프**: 한 시즌 동안은 편중이 생겨도 모릅니다. 대신 추측이 아니라 실측으로 판단하게 됩니다
- ⭐ **볼트 승격 권장** — 출처 다변화 방침에 영향을 주는 결정입니다

#### 사이트맵을 디스크에 캐시하지 않고 프로세스 안에서만 재사용

- **문제**: 29곳을 순회하면서 사이트맵 5곳을 매번 받으면 145회 요청이 됩니다
- **선택**: 프로세스 안에서 1회만 받아 재사용하고, 디스크에는 저장하지 않습니다. 실행당 요청 5건
- **대안**:
  - 디스크 캐시 — 재실행 비용이 더 줄지만, 블로그에 새 글이 계속 올라오므로 재실행하면 달라지는 상태입니다. 저장하면 새 글을 영영 못 봅니다
- **트레이드오프**: 소스 일부가 일시적으로 실패하면 그 결과가 실행이 끝날 때까지 유지됩니다. 다음 실행에서 자동으로 다시 시도합니다
- **부작용 확인됨**: 5곳 중 4곳이 실패한 상태로 로드되면 그 실행 내내 1곳 분량만 보게 됩니다. 피해는 절감 손실뿐이고 결과는 웹 검색 폴백으로 정상이라 현행 유지로 판단했습니다

#### 테스트 네트워크 차단을 autouse 픽스처로

- **문제**: `discover_sitemap`이 생기면 이를 모르는 기존 테스트가 실제 사이트맵을 받으러 나갑니다
- **선택**: `conftest.py`의 autouse 픽스처가 모든 테스트에서 `_sitemap_urls`를 빈 목록으로 둡니다. 사이트맵을 쓰는 테스트만 직접 덮어씁니다
- **대안**:
  - 각 테스트에서 개별 monkeypatch — 새 테스트를 추가할 때마다 빠뜨릴 수 있고, 빠뜨리면 조용히 네트워크를 씁니다
- **트레이드오프**: 인자 순서를 바꾸는 실수를 이 픽스처가 가릴 수 있습니다. 빈 목록이면 매칭 본문이 실행되지 않기 때문입니다

### 🔧 주요 변경사항 상세

#### 웹 검색 지연 호출이 절감의 실체

`_try_candidates`가 사이트맵 후보에서 `True`를 반환하면 `discover_cached` 호출 자체에 도달하지 않습니다. 인자로 미리 평가되는 형태가 아니라 분기 안에 있어야 실제로 건너뜁니다.

종단 검증에서 이를 확인했습니다. 시드 URL이 빈 대학 1곳을 별도 시드 파일과 출력 디렉터리로 실행한 결과입니다.

```
discovery : sitemap
source_url: memogipost.tistory.com/entry/2026-홍익대학교-서울캠퍼스축제
라인업    : 12건
discovered/ : 생성되지 않음  ← 웹 검색이 호출되지 않았다는 증거
```

**특이사항**:
- `discovered/` 디렉터리가 만들어지지 않은 것이 근거입니다. 웹 검색이 돌면 반드시 그 캐시가 생깁니다

#### 실패 의미 보존

소스가 셋이 되면서 실패 처리가 섞일 위험이 있었습니다. 세 가지를 그대로 유지했습니다.

- 시드 URL이 실패하고 어느 후보도 검증을 통과하지 못하면 **시드 URL의 실패 사유**가 남습니다. `no_candidate`로 덮이지 않습니다. `no_candidate`는 시드 URL이 애초에 없었을 때만 설정됩니다
- `discover_cached`가 `None`(탐색 자체가 실패)을 반환하면 즉시 반환하며 결과를 캐시하지 않습니다. 다음 실행에서 재시도합니다
- 사이트맵의 "후보 없음"과 "후보가 전부 실패"는 같은 폴백으로 합류합니다. 둘 다 "다음 소스로 넘어가라"는 뜻이기 때문입니다

`_try_candidates`는 어느 후보도 통과하지 못하면 `record`를 건드리지 않습니다. 첫 번째 규칙이 여기에 의존합니다.

#### 절감 대상은 검색 호출이지 추출 호출이 아님

사이트맵 탐색 자체는 LLM을 쓰지 않지만, 후보가 채택되려면 `_attempt_url` → `extract()` → `call_claude()`를 그대로 거칩니다.

- 성공 케이스는 상쇄입니다. 어느 경로로 채택되든 추출 1콜이 필요합니다
- 실패 케이스는 순증입니다. 사이트맵 후보가 전부 검증에서 떨어지면 그 시도에 쓴 추출 호출을 버리고 웹 검색으로 넘어갑니다

줄어드는 것은 60초짜리 검색 호출과 그 세션 비용입니다.

### 📦 의존성 변경

없음. 표준 라이브러리와 기존 `requests`만 사용하며 `requirements.txt`는 변경하지 않았습니다.

### 🧪 테스트 및 검증

단위 테스트 112개 통과(기존 95 + 신규 17). 네트워크와 LLM 호출은 전부 monkeypatch했습니다.

| 대상 | 확인 |
| --- | --- |
| 엄격 매칭 | `2026-고려대학교-대동제`는 잡고 `2026-고려대-과학기술대학-대동제`·`2026-서울대공원-장미원축제`는 잡지 않음 |
| 연도·경로 필터 | 다른 연도, `/category/` 등 비-글 URL 제외 |
| 차단 도메인 | 기존 `_is_blocked` 적용 |
| 메모리 캐시 | 서로 다른 두 대학을 연달아 조회해도 fetch는 1회 |
| 소스 장애 | 5곳 중 일부가 실패해도 예외 없이 나머지로 진행, 전부 실패하면 빈 목록 |
| 지연 호출 | 사이트맵이 성공하면 `discover_cached`를 호출하지 않음(호출 시 예외를 던지는 대역으로 검증) |
| 폴백 | 사이트맵 후보가 전부 실패하면 웹 검색으로 넘어감 |
| 실패 의미 | 시드 실패 사유 보존, 탐색 실패(`None`)는 캐시하지 않고 즉시 반환 |

종단 검증은 위 §🔧에 기록했습니다. 실제 `output/`을 건드리지 않도록 별도 시드 파일과 출력 디렉터리로 실행했습니다.

### 📌 참고사항

- **이번 시즌에는 이 기능이 발동하지 않습니다.** 사이트맵이 커버하는 17곳은 전부 시드 URL을 이미 갖고 있고, 시드 URL이 없는 8곳(고려대·중앙대·한국외대·숙명여대·성신여대·동덕여대·서경대·삼육대)은 사이트맵에 0건입니다. 교집합이 비어 있습니다. 값어치는 연도가 바뀔 때 나옵니다
- 그 때문에 계획에 적었던 `--limit 5` 스모크로는 검증이 불가능했고, 격리된 시드 파일로 따로 확인했습니다
- **연도를 올릴 때 `universities.csv`의 `url` 컬럼을 비우세요.** 안 비우면 죽은 시드 URL 21개를 전부 수집하고 추출 호출까지 한 뒤에야 검증에서 떨어집니다. 비우면 그 21건이 절약되고 바로 사이트맵 단계로 갑니다
- **커버리지는 늘지 않습니다.** 현재 실패 중인 3곳은 5개 블로그 어디에도 없습니다
- **후속 과제: 캠퍼스 판별.** 다른 캠퍼스 글이 채택될 수 있는데 `verify`가 대학명과 연도만 봅니다. 지금은 다캠퍼스 대학(고려대·중앙대·한국외대)이 전부 사이트맵 미커버라 실제 위험이 없지만 다음 시즌 전에 다뤄야 합니다. `universities.csv`에 안 쓰는 `campus` 컬럼이 이미 있습니다
