# charset 폴백과 하루 축제 추론으로 빈 값을 채운다

### 📌 작업 개요

- **이슈**: #24
- **브랜치**: `fix_24_채울_수_있는_값이_빈다_charset_폴백과_하루_축제_추론`
- **범위**: 크롤러가 채울 수 있는데 못 채우던 값 2종을 고친다
- **결과**: 산출물 전체 `day` 빈 행 20 → 18, 이화여대 `end_date` 확보. 한국외대는 미해결(원인이 달랐다)

### 🎯 구현 목표

백엔드 임포트에서 `INVALID`로 떨어지는 값 중 **크롤링으로 얻을 수 있는 것**을 가려내 채운다. 원문에 없는 값은 대상이 아니며 관리자 교정(`greedy-team/festa-backend#106`)이 받는다.

### ✅ 구현 내용

#### 1. charset 없는 응답의 인코딩 (`fetch.py`)

`html = resp.text` 한 줄이 문제였다. requests는 `Content-Type`에 `charset`이 없으면 RFC 2616대로 **ISO-8859-1**을 쓰고 HTML·XML이 선언한 인코딩은 보지 않는다.

```
Content-Type      : text/html      ← charset 없음
resp.encoding     : ISO-8859-1     ← requests의 폴백
apparent_encoding : utf-8
meta charset      : UTF-8
```

한국어 본문이 통째로 깨진 채 LLM에 들어갔다. **오류가 아니라 값이 비는 형태로만 드러나서** 지금까지 안 보였다.

`_decode()` 헬퍼로 뽑고 `fetch_body`·`fetch_text`가 함께 쓰게 했다. **이슈는 `fetch_body`만 지목했으나 사이트맵 경로도 같은 코드였다** — 한 곳만 고치면 나머지가 남는 자리다.

```python
def _decode(resp: "requests.Response") -> str:
    if "charset" not in resp.headers.get("Content-Type", "").lower():
        resp.encoding = resp.apparent_encoding or "utf-8"
    return resp.text
```

`resp.encoding`이 아니라 **헤더를 보는 이유** — 서버가 진짜로 `charset=ISO-8859-1`을 선언한 경우까지 덮지 않기 위해서다.

#### 2. 하루 축제의 확정값 추론 (`extract.py`)

원문이 날짜 하나만 적으면 `end_date`와 각 출연자의 `day`가 비어 나왔다. 정보가 없는 게 아니라 **하루라는 사실에서 확정되는 값**이다.

프롬프트에 두 줄을 더했다.

- `start_date / end_date`: 하루만 열리는 축제로 읽히면 `end_date`를 `start_date`와 같게
- `day`: 축제가 하루만 열리면 일차 표기가 없어도 모든 출연자의 `day`는 1

#### 3. `SCHEMA_VERSION` 2 → 3 (`crawl.py`)

2번이 추출 결과를 바꾸므로 재수집이 필요하다. 좌표 때(#18) 올리지 않은 것과 **반대 경우**다 — 그때는 시드 전용 필드라 LLM 결과가 한 글자도 안 바뀌었다.

### 🧭 결정 기록 (ADR)

**`verify()`를 엄격하게 만들지 않았다.** 「필수 필드가 없으면 `flag`를 실패로 내려 백엔드에 `INVALID`가 안 가게 한다」를 검토했다가 기각했다.

백엔드에 관리자 축제·라인업 교정 API가 생기면(`greedy-team/festa-backend#106`) **부분 데이터라도 넘어가야 사람이 마저 채운다.** verify를 조이면 서울대 12명·서울시립대 6명이 CSV에서부터 사라져 채울 원재료조차 없어진다. *크롤링은 초안 생성기이고 최종 신뢰는 사람이 담보한다* 는 설계 축을 그대로 따랐다.

**시드 `url`을 채우는 안도 기각했다.** `discovered/*.json`의 후보를 전수 열어 확인한 결과 쓸 것이 없었다 — 고려대 후보 2건은 *"입실렌티는 라인업을 사전에 공개하지 않는 것이 전통"* 이라 아티스트 0명, 성신여대 후보 2건은 전국 종합글인데 본문에 '성신'이 0회, 삼육대 유일 후보는 2025년 글이라 `verify()`가 옳게 걸렀다.

### 🧪 테스트 및 검증

### 📌 참고사항

#### 정정 — 한국외대 `start_date`는 인코딩 탓이 아니었다

charset 수정은 작동해 본문이 정상으로 들어오지만 `start_date`는 여전히 빈다. **원문에 없기 때문이다.** 그 글은 에스파 팬 커뮤니티 글이고 날짜 표기가 `5월 29일`(앨범 발매)·`6월 2일`(에스파 출연, `DAY 2`)뿐이다. 프롬프트 첫 규칙이 *"명시되지 않은 값은 반드시 null"* 이라 LLM이 옳게 비웠다.

**이슈 본문의 「인코딩 탓」은 잘못된 귀속이다.** 인코딩 버그는 실재했고 고쳤지만 그 값이 빈 이유는 별개였다. 한국외대는 「원문에 없어 사람이 채워야 하는」 쪽으로 옮겨간다.

#### 재크롤이 멱등이 아니다

같은 원문인데 추출 결과가 흔들렸다.

| 축제 | 라인업 | 성격 |
| --- | --- | --- |
| 한양대 | 15 → 18 | **개선** — `H1GHR MUSIC[pH-1, 빅나티, 릴보이, 우디고차일드]` 한 행이 멤버 4행으로 분해 |
| 홍익대 | 18 → 12 | **판정 차이** — 아래 |
| 서강대 · 서울여대 | +1씩 | 미확인 |
| 명지대 | −1 | 미확인 |
| 서울대 | 12 → 12 | **후퇴** — `day=3`이던 2행이 빈 값이 됐다 |

거의 모든 축제의 `description`이 바뀌었고 여러 곳에서 `name`·`venue_name`·`verification_method`·`admission_raw`도 달라졌다.

**홍익대에서 빠진 8팀은 유실이 아니다.** 전부 원문에 있고 원문이 이렇게 적는다 — `학생 무대 : 오버스, 미녀와 야수, 7dren 등 실력파 중앙동아리 및 공연예술학부`. 교내 동아리 무대를 라인업에 넣을지는 **제품 판정**인데 정해진 적이 없어 실행할 때마다 LLM이 다르게 판단한다. 원문에 `등`도 붙어 있어 애초에 전수가 아니다.

#### 남기는 문제 둘 (별건)

1. **`SCHEMA_VERSION`을 올리면 프롬프트 한 줄 고칠 때마다 29곳 전체의 추출이 흔들린다.** 이번엔 2건 얻고 1건 후퇴 + 3건 미확인 변동이었다. 재수집 범위를 좁히거나 변동을 diff로 잡는 장치가 필요하다
2. **「학생 무대를 라인업에 포함하는가」가 정해진 적이 없다.** 정하지 않으면 재크롤마다 계속 흔들린다

후퇴분(서울대 `day` 2행, 홍익대 판정)은 관리자 교정(`greedy-team/festa-backend#106`)으로 넘긴다.
