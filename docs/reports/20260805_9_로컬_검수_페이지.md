### 📌 작업 개요

크롤러 산출물 CSV를 브라우저에서 훑고 문제 행만 골라 다시 돌리는 로컬 관리자 페이지 추가.
전제로 `lineup.csv`의 조인 키를 `university + year`에서 `festival_id`로 정정.

검수는 지금까지 CSV를 엑셀로 열어 `flag != ok` 행을 찾고 `source_url`을 브라우저에 붙여
원본과 대조하는 흐름이었다. 축제 29곳·라인업 219행에서 이미 번거롭고, 대상이 늘면 검수가
파이프라인 전체의 병목이 된다.

**보고서 파일**: `docs/reports/20260805_9_로컬_검수_페이지.md`

### 🎯 구현 목표

- `festivals.csv`↔`lineup.csv`를 안정적인 식별자로 조인
- 검수 대상(`flag != ok`, `discovery = search`, `needs_review`)을 한 화면에서 걸러 보기
- 원본 글과 추출 결과를 나란히 대조
- `crawl`·`enrich` 전체 실행과 대학 1곳 재실행을 화면에서 수행
- 외부 의존성 추가 없이 (`requirements.txt` 불변), 배포 대상 없이 로컬에서만

### ✅ 구현 내용

#### `festival_id` 도입

- **파일**: `crawl.py`
- **변경 내용**: `festival_id(university, year) -> "<대학명>-<연도>"` 헬퍼 추가.
  `FESTIVAL_FIELDS` 첫 컬럼에 `festival_id` 추가, `LINEUP_FIELDS`에서 `university`·`year`·
  `festival_name`을 빼고 `festival_id`로 대체 (10 → 8 컬럼)
- **이유**: 파이프라인 문서 4.1 개정판의 축제 레코드는 `festival_id`를 키로 `lineup[]`을
  품는 구조인데, 구현은 식별자 없이 대학명 문자열로 조인하고 있었다. 표기가 바뀌면 조인이
  오류 없이 조용히 깨지고, 대학 아닌 축제로 넓힐 때 스키마가 맞지 않는다

`enrich.py`는 `crawl.LINEUP_FIELDS`를 import하므로 코드 변경 없음.

#### CSV 원자적 쓰기

- **파일**: `crawl.py`
- **변경 내용**: `write_csv`가 대상 파일을 직접 열어 truncate하던 것을, 같은 디렉터리의
  임시 파일에 쓴 뒤 `os.replace()`로 교체하도록 변경. 실패 시 임시 파일 정리 후 재발생
- **이유**: 페이지가 CSV를 읽는 도중 `crawl.py`가 같은 파일을 쓰면, 독자는 깨진 CSV가 아니라
  **0바이트 또는 일부만 있는 CSV**를 본다. `csv.DictReader`는 그것을 예외 없이 "행이 적은
  정상 파일"로 읽어 화면에 축제 0건이 뜬다. 원자적 교체는 독자가 항상 완전한 파일만 보게 한다

#### 서버 (`serve.py`)

- **파일**: `serve.py` (신규)
- **변경 내용**: `http.server` 기반 로컬 서버. `GET /`(페이지), `GET /api/data`(CSV 3종 JSON),
  `POST /api/run`(잡 시작), `GET /api/log?from=N`(진행 로그). `127.0.0.1`에만 바인드
- **이유**: 표준 라이브러리만으로 충분하고, 배포 대상이 없는 레포에 웹 프레임워크를 들이지 않음

#### 화면 (`review.html`)

- **파일**: `review.html` (신규)
- **변경 내용**: 바닐라 JS 단일 페이지. 필터 4종(`문제만`/`검색출처`/`전체`/`아티스트`),
  축제 상세 + 라인업(`artist_canonical ← artist_raw`), 원본 iframe + 새 탭 링크,
  실행 버튼, 로그 폴링, `j`/`k` 목록 이동
- **이유**: 빌드 도구 없이 한 파일로 끝나는 규모. 진입 시 `문제만`이 켜져 있어 사람이 볼
  것부터 보여준다

#### 기동 스크립트 (`admin.sh`)

- **파일**: `admin.sh` (신규)
- **변경 내용**: venv가 없으면 만들고 `serve.py`를 띄운다. 실행 위치 무관, 인자 그대로 전달
- **이유**: 크롤러를 쓰는 정상 경로를 명령 하나로 통일

### 🧭 결정 기록 (ADR)

#### `festival_id`만 도입하고 `organizer_id`·`festival_type`은 보류

- **문제**: 파이프라인 문서 4.1 개정판은 `festival_id`·`organizer_id`·`organizer_name`·
  `festival_type` 네 필드를 요구하는데 구현에는 하나도 없었다
- **선택**: `festival_id` 하나만 도입. 나머지 셋은 보류
- **대안**:
  - 네 필드 전부 추가 — 현재 전 행이 `UNIVERSITY` 상수이고 `organizer_id`가 가리킬
    주최 기관 마스터가 존재하지 않아, 값 없는 컬럼만 늘어난다
  - 현행 유지 — 대학명 문자열 조인이 깨지는 위험이 남는다
- **트레이드오프**: 대학 아닌 축제(`LOCAL`/`MUSIC`/`CULTURE`)가 들어올 때 스키마를 한 번 더
  손봐야 한다. 그때 `festival_type`이 비로소 변수가 된다
- ⭐ **볼트 승격 권장** — 스키마 결정이며 백엔드 적재 계약에 직결

#### 화면을 읽기 전용으로 두고 값 교정은 백엔드 어드민에 위임

- **문제**: 검수 화면에서 값을 고칠 수 있어야 하는가
- **선택**: 읽기 전용. 화면의 책임은 "무엇이 잘못됐는지 찾고 다시 돌리는 것"까지
- **대안**:
  - 화면에서 CSV 직접 수정 — `crawl` 재실행 때 CSV가 통째로 덮어써져 수정분이 날아간다
  - 별도 오버라이드 파일에 수정 누적 — 재실행에 안전하지만, 백엔드 어드민이 어차피 교정
    기능을 가지면 같은 교정을 두 곳에서 하게 된다
- **트레이드오프**: 오타 하나를 고치려 해도 크롤러 화면에서는 불가능하고 다음 단계로 넘겨야 한다
- ⭐ **볼트 승격 권장** — 크롤러와 백엔드 어드민의 역할 경계를 정하는 결정

#### 행 단위 재실행을 캐시 삭제로 구현 (`crawl.py` 무변경)

- **문제**: 대학 1곳만 다시 돌리는 기능이 필요한데 `crawl.py`에는 `--only` 옵션이 없다
- **선택**: 해당 대학의 캐시 파일(`output/raw/<대학>.json`, 필요 시 `discovered/`도)을 지우고
  `crawl.py`를 통째로 실행. 나머지 28곳은 캐시 히트로 즉시 지나가고 CSV 재생성까지 따라온다
- **대안**:
  - `crawl.py`에 `--only <대학>` 플래그 추가 — 파이프라인 코드에 화면 전용 분기가 생기고,
    CSV 재생성 경로를 따로 만들어야 한다
- **트레이드오프**: "1곳 재실행"이 실제로는 전체 순회다. 캐시 히트라 0.3초면 끝나지만,
  캐시가 비어 있으면 의도치 않게 전체 크롤이 된다
- ⭐ **볼트 승격 권장** — 코드만 봐서는 왜 전체를 도는지 알 수 없는 비직관적 선택

#### 잡 동시 실행을 프로세스 하나로 제한

- **문제**: `crawl`과 `enrich`는 같은 구독 세션 한도를 쓴다. 둘을 동시에 띄우면 양쪽이 깨진다
- **선택**: 전역 잡 슬롯 하나. 실행 중 요청은 `409`. 확인과 프로세스 생성을 같은 락 안에서 수행
- **대안**:
  - 큐잉 — 로컬 단일 사용자 도구에 대기열은 과하다
  - 제한 없음 — 세션 한도가 즉시 소진된다
- **트레이드오프**: `enrich`를 돌리는 동안 특정 대학 재수집을 걸 수 없다
- ⭐ **볼트 승격 권장** — 세션 한도는 이 프로젝트의 반복되는 운영 병목

#### `POST /api/run`에 `Content-Type` 검사

- **문제**: 인증 없는 로컬 서버라, 사용자가 브라우저로 다른 사이트를 보는 동안 그 페이지가
  교차 출처 폼으로 크롤 실행이나 캐시 삭제를 걸 수 있다
- **선택**: `application/json`이 아닌 요청은 본문을 읽기 전에 400. 단순 폼은 이 헤더를 만들 수 없다
- **대안**:
  - `Origin` 헤더 검사 — 더 엄격하지만 헤더가 없는 정상 요청 처리 규칙을 추가로 정해야 한다
  - 무방비 — 세션 한도를 남이 소진시킬 수 있다
- **트레이드오프**: `curl`로 수동 호출할 때 헤더를 명시해야 한다
- ⭐ **볼트 승격 권장** — 로컬 전용 도구의 신뢰 경계 판단 기준

### 🔧 주요 변경사항 상세

#### 재실행 버튼이 둘인 이유

`다시 돌리기`는 `output/raw/<대학>.json`만, `탐색부터`는 `output/discovered/<대학>.json`까지
지운다. `mismatch`처럼 출처는 맞고 추출이 틀린 행은 전자로 충분하고, `no_candidate`는 후보
목록 자체가 쓸모없었으므로 후자가 필요하다. 서버가 `flag`를 보고 자동으로 고르면 숨은 로직이
되고, 왜 탐색에 60초를 더 썼는지 설명할 수 없게 된다.

**특이사항**:
- 캐시 삭제는 파일이 없어도 통과한다 (`missing_ok=True`). 버튼을 두 번 눌러도 무해하다
- 재실행 대상 대학명은 `universities.csv`에 실재하는 값만 받는다. 목록에 없으면 400이며
  파일 경로 조립에 도달하지 않는다 (정규화·이스케이프로 막지 않음)

#### 원본 표시

`source_url`을 iframe으로 임베드하고 `새 탭 ↗` 링크를 항상 함께 둔다. `sandbox="allow-scripts"`
(동일 출처 권한 미부여) + `referrerpolicy="no-referrer"`를 걸어 남의 블로그 스크립트에 권한을
주지 않는다. 이 때문에 임베드가 비는 사이트가 많으며, 새 탭이 실질적 주경로다.

**특이사항**:
- 크롤링한 문자열은 전부 이스케이프 후 DOM에 넣는다
- `href`/`src`는 이스케이프와 별개로 `http(s)` 스킴만 허용한다. HTML 엔티티 이스케이프는
  `javascript:` 스킴을 막지 못하기 때문이다

#### `enrich.py` 헤더 선검증

`collect_raw_names()`는 `output/raw/*.json`을 읽어 스키마와 무관하게 동작하므로, 구버전
`lineup.csv`가 남아 있으면 대형 LLM 호출(실측 578초)을 마친 **뒤에** 컬럼 불일치로 실패해
결과를 통째로 잃는다. `normalize()` 전에 `lineup.csv` 헤더를 검사해 즉시 중단하도록 변경.

### 📦 의존성 변경

없음. 표준 라이브러리만 사용하며 `requirements.txt`는 변경하지 않았다.

### 🧪 테스트 및 검증

- 단위 테스트 95개 통과 (기존 70개 + 신규 25개)
- 신뢰 경계 테스트: `../../etc/passwd` 같은 값이 400이며 대상 파일이 실제로 남아 있는지 확인
- 원자성 테스트: 교체 실패 시 기존 파일 내용이 보존되고 임시 파일이 남지 않는지 확인
- 동시성 테스트: 잡 시작 경합에서 두 번째 요청이 409를 받는지, `snapshot()`이 `running`과
  `returncode`가 모순되는 값을 내지 않는지 확인
- HTTP 스모크: 서버 기동 후 `GET /`, `GET /api/data`, `GET /api/log?from=0`,
  `GET /api/log?from=abc`(400), 잘못된 대학명 `POST /api/run`(400), 잘못된 `Content-Type`(400)
- 스키마 마이그레이션 실행: `crawl.py` 캐시 전용 0.31초, `festivals` 29행·`lineup` 219행 재생성,
  양쪽에 `festival_id` 존재, 조인 검증 (`서울대학교-2026` → 12/219)

**미검증**: 브라우저 수동 점검(필터 표시, `j`/`k` 이동, iframe 폴백, 아티스트 정렬, 실제
재탐색 실행, 동시 실행 경고)은 사람이 직접 수행해야 한다.

### 📌 참고사항

- **기존 `output/`는 구 스키마다.** `festival_id` 도입 전에 만든 CSV가 남아 있으면 조인이
  전부 참이 되어 축제마다 라인업 219행이 표시된다. `crawl.py`를 한 번 다시 실행해 재생성한다.
  `output/raw/*.json` 캐시가 있으면 LLM 호출 없이 1분 미만에 끝난다
- 크롤러의 책임은 검토를 마친 CSV까지다. 백엔드는 현재 스켈레톤 상태라 CSV를 받는 기능이
  없으며, 지금은 CSV가 최종 산출물이다
- 브레인스토밍 중 나온 **사이트맵 기반 탐색**은 별도 이슈로 분리했다. 블로그의 `/search`는
  `robots.txt`로 차단돼 있으나 `sitemap.xml`은 열려 있어, 요청 1건으로 시드 29곳 중 23곳의
  후보를 얻을 수 있다. 커버리지는 늘지 않고 탐색 시간과 세션 한도 소모만 줄어든다.
  다만 단일 블로거 의존이 되돌아올 수 있어 `discovery` 컬럼으로 편중을 측정한 뒤 순서를
  재조정하는 방식을 제안한다
