# 연도별 출력 분리 + 아티스트 정규화 보존

작성일: 2026-08-06

## 문제

두 가지 데이터 손실이 있다.

### 1. crawl 재실행이 enrich 결과를 지운다

`enrich.py:88`이 `lineup.csv`의 `artist_canonical`을 정규화 값으로 채우는데,
`crawl.py:167`이 다시 `artist_canonical = artist_raw`로 되돌린다.
캐시(`output/raw/*.json`)에는 `artist_raw`만 있어서 복원되지 않는다.

실측 (2026-08-06):

```
lineup.csv 219행 중 107행이 정규화된 상태
→ crawl.py 재실행 1회로 107행 전부 원문으로 리셋
```

`enrich.py`는 578초짜리 LLM 호출 1건이다. 그리고 검수 페이지의 `다시 돌리기` 버튼이
대학 1곳 재실행에도 crawl 전체를 돌리므로(DEC-0021), 한 곳을 고칠 때마다 29곳
정규화가 전부 날아간다. 에러도 경고도 없이 조용히 사라진다.

`enrich.py`가 만드는 `result.mapping`이 이 정보의 유일본이며, 지금은 쓰고 버려진다.
`artists.csv`의 `aliases` 컬럼은 대체가 되지 않는다 — 역인덱스로 복원을 시도하면
219행 중 61행이 실패한다 (`트리플에스(tripleS)` 같은 원문 표기가 aliases에 없음).

### 2. 연도가 바뀌면 이전 연도가 덮어써진다

`output/raw/`는 대학당 JSON 1개, CSV도 대학당 1행이다. 시드의 `year`를 2027로 바꾸면
캐시가 무효화되고(`crawl.py:98`) 2026 데이터는 사라진다. 연도별 히스토리가 없다.

## 목표

- 연도별 산출물이 서로를 덮지 않는다
- crawl을 몇 번 다시 돌리든 `artist_canonical`이 유지된다
- 2027 정규화가 2026에서 이미 정한 표기를 재사용한다 (매년 578초를 다시 쓰지 않는다)

## 설계

### 파일 배치

```
crawler/
  universities-2026.csv          # 기존 universities.csv 를 rename
  universities-2027.csv          # 내년에 추가. 2026 파일은 동결
  output/
    artists.csv                  # 연도 공통 마스터 (누적)
    artist_mapping.json          # 연도 공통 표기→정식명 매핑 (누적, 신규)
    2026/
      festivals.csv
      lineup.csv
      raw/*.json
      discovered/*.json
    2027/ ...
```

아티스트 마스터와 정규화 매핑은 연도와 무관하다 (10CM는 매년 10CM). 연도 폴더 바깥에 둔다.

새 연도 시드를 만들 때는 `url` 컬럼을 비운 채로 시작한다. 이슈 #11 보고서에 기록된 대로,
시드 URL 21개 중 19개가 주소에 연도가 박힌 특정 연도 글이라 연도가 바뀌면 전부 검증에서
떨어진다. 비우지 않으면 죽은 URL 21건을 수집하고 LLM 추출까지 호출한 뒤에야 실패한다.
비우면 곧바로 사이트맵 탐색 단계로 간다.

### 인터페이스

손잡이는 `--year` 하나다. 시드 경로와 출력 폴더가 둘 다 여기서 유도된다.

```bash
python crawl.py --year 2026     # universities-2026.csv → output/2026/
python enrich.py                # 전 연도 대상, 인자 없음
python serve.py --year 2026
```

`--input`·`--output-dir` 인자는 제거한다. 두 개를 따로 받으면 연도가 어긋난 조합이
가능해진다.

시드의 `year` 컬럼은 남기되 `--year`와 다르면 즉시 에러 — 같은 값을 두 곳에 적게 되지만,
시드 파일을 잘못 고르는 사고를 여기서 잡는다.

`enrich.py`에 `--year`가 없는 이유: 매핑과 마스터가 연도 공통이라 전 연도의 `raw/`를
한 번에 훑는 것이 맞다.

### 정규화 보존 흐름

`artist_mapping.json`은 평면 객체다: `{"원문표기": "정식표기"}`.

```
enrich.py   raw/*.json (전 연도) → 이름 수집
            → 매핑의 키에 이미 있는 이름은 제외, 새 이름만 LLM에 전달
              (프롬프트에 기존 정식 표기 목록을 함께 넣는다 —
               그래야 "십센치"가 기존 "10CM"에 붙는다)
            → result.mapping 을 artist_mapping.json 에 병합 저장
            → 모든 연도 폴더의 lineup.csv 갱신

crawl.py    build_lineup_rows 가 artist_mapping.json 을 읽어
            artist_canonical 을 채운다. 매핑에 없으면 artist_raw.
```

양쪽이 모두 `lineup.csv`를 쓴다. enrich가 쓰는 것은 정규화 직후 crawl 재실행 없이
결과가 보이게 하기 위함이고, crawl이 쓰는 것은 재실행이 정규화를 지우지 않게 하기
위함이다. 둘 다 같은 매핑 파일을 출처로 삼으므로 결과는 일치한다.

이러면 순서 의존이 사라진다. crawl을 몇 번 다시 돌려도 매핑에서 매번 다시 채워진다.

`is_secret` 행은 지금과 같이 정규화 대상이 아니다 (`collect_raw_names`가 제외).
그 행의 `artist_canonical`은 `artist_raw`로 남는다.

### 검토한 대안

| | 방식 | 판정 |
|---|---|---|
| A | 매핑을 `artist_mapping.json`에 누적 저장하고 crawl이 읽어 채운다 | **채택** |
| B | crawl이 기존 `lineup.csv`를 읽어 이전 canonical을 보존 | 탈락 — 연도 폴더가 새로 생기면 읽을 이전 파일이 없다. 연도 공통 누적과 어긋난다 |
| C | `lineup.csv`에서 `artist_canonical`을 빼고 소비 시점에 `artists.csv`로 조인 | 탈락 — aliases로 61행이 복원 안 되는 것이 실측으로 확인됐고, review.html과 어드민 입력 흐름까지 번진다 |

### 함께 바뀌는 곳

`serve.py`가 `--year`를 받아:

1. `OUT_DIR = output/<year>` (`serve.py:145`)
2. 허용 목록을 `universities-<year>.csv`에서 로드 (`serve.py:213`)
3. crawl 서브프로세스에 `--year` 전달 (`serve.py:60-64`, 지금은 인자 없이 실행)

`review.html`은 손대지 않는다.

### 에러 처리

| 상황 | 동작 |
|---|---|
| `universities-<year>.csv` 없음 | 중단 + 존재하는 연도 시드 나열 |
| `--year`와 시드 `year` 컬럼 불일치 | 중단 |
| `artist_mapping.json` 없음 | 빈 매핑으로 진행 (첫 실행의 정상 상태) |
| `artist_mapping.json` 파싱 실패 | **중단.** 조용히 빈 매핑으로 넘어가면 이 스펙이 고치려는 소실이 그대로 재발한다 |
| `output/<year>/` 없음 | 생성 |

## 기존 데이터 마이그레이션

LLM 재실행이 필요 없다. 실측으로 확인했다 — 현재 `lineup.csv`에서
`{artist_raw: artist_canonical}` 167개를 복원할 수 있고, 이것이 `raw/`에서 뽑히는
이름 165개를 전부 덮는다 (미커버 0건).

(위 "문제"의 107행과 여기 167개는 다른 것을 센다. 107은 `artist_canonical != artist_raw`인
lineup 행 수, 즉 표기가 실제로 바뀐 행이다. 167은 매핑 키 개수로, 정규화 결과가 원문과
같은 표기까지 포함한다.)

```
1. git mv universities.csv universities-2026.csv     # 유일하게 커밋되는 변경
2. mkdir output/2026
   mv output/{festivals.csv,lineup.csv,raw,discovered} output/2026/
3. output/2026/lineup.csv 에서 artist_mapping.json 생성 (167개)
4. output/artists.csv 는 output/ 에 그대로 둔다
```

`output/`은 gitignore되어 있어 2~4는 로컬 작업이다.

## 검증

현재 테스트 112개. `out_dir` 시그니처를 쓰는 `test_crawl.py`·`test_enrich.py`·
`test_serve.py`가 따라 바뀐다.

새 테스트 4개. 첫 번째가 이 작업의 존재 이유이므로 RED부터 시작한다.

1. enrich로 canonical을 채운 뒤 crawl을 다시 돌려도 `artist_canonical`이 유지된다
   ← 현재 깨져 있는 동작
2. `--year 2027`인데 시드 `year` 컬럼이 2026이면 에러
3. enrich가 매핑에 이미 있는 이름은 LLM 프롬프트에 넣지 않는다
4. `--year 2026` 실행이 `output/2027/`을 건드리지 않는다

완료 판정: 위 4개가 통과하고 기존 112개가 전부 통과한다.

## 범위 밖 — 알려진 미해결

`--limit N`이 CSV를 N행으로 잘라내는 문제(`crawl.py:207`, `run()`이 처리한 행만 CSV에
쓰므로 나머지 대학 행이 사라진다). 연도 폴더로도 매핑 보존으로도 해결되지 않는다.
캐시가 살아 있어 전체 재실행으로 복구되고 스모크 전용 옵션이라 이번 범위에서 제외한다.
