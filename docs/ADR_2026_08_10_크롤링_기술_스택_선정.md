# ADR_2026_08_10 : 크롤링 기술 스택 선정

### 1. 문제 정의 (Context)

대학 축제 정보(축제 상세 + 라인업)를 모아 서비스에 넣어야 한다. 문제는 **출처의 성격**이다.

- 원천이 **개인 블로그 글**이다. 대학 공식 API도, 공용 데이터셋도, 일관된 HTML 구조도 없다.
- 같은 정보가 블로그마다 다른 문장으로 적힌다. `5.27~29` · `오는 27일부터 사흘간` · `DAY1` ·
  `첫날 라인업` — 정규식으로 규칙을 짜면 새 블로그가 나올 때마다 깨진다.
- 대상은 **서울 상위 대학 29곳, 연 1회 시즌**이다. 초당 수천 건이 아니라 연간 수십 건이다.
- 축제 정보는 **틀리면 사용자가 헛걸음한다.** 날짜·장소가 잘못된 데이터를 자동 발행할 수 없다.

즉 풀어야 할 핵심 문제는 **"비정형 한국어 산문에서 구조화된 레코드를 뽑되, 틀린 값이 자동으로
서비스에 실리지 않게 하는 것"** 이다. 처리량이나 실시간성은 문제가 아니다.

### 2. 결정 (Decision)

**Python 로컬 배치 + 규칙 기반 수집 + LLM 구조화 + 사람 검수**의 조합을 쓴다.

| 층 | 선택 | 역할 |
| --- | --- | --- |
| 언어 | Python 3.13 (venv + `requirements.txt`) | |
| 수집 | `requests` + `urllib.robotparser` | HTTP, robots.txt 준수, 호스트당 3초 간격 |
| 본문 추출 | `beautifulsoup4` (셀렉터) → `trafilatura` (폴백) | HTML → 본문 텍스트·이미지·인스타 핸들 후보 |
| 구조화 | 로컬 `claude` CLI 헤드리스 호출 | 본문 산문 → JSON |
| 검증 | `pydantic` | LLM 응답 스키마 검증, 열거값 강제 |
| 산출 | 표준 라이브러리 `csv` | 검수용 CSV 3종 |
| 테스트 | `pytest` | 단위 테스트 160개 |

**역할 경계가 이 결정의 핵심이다. LLM은 글을 읽는 일만 하고, 판정은 전부 파이썬이 한다** —
스키마 검증, 역방향 검증(`verify`), flag 부여, 캐시 판정, 산출물 쓰기. LLM이 URL을 지어내거나
엉뚱한 대학 글을 읽어도 코드가 걸러낸다.

그리고 **크롤러는 초안 생성기다.** 최종 산출물은 CSV이고, 사람이 검수 화면에서 확인한 뒤
백엔드 어드민에 올린다. 자동 발행 경로는 두지 않는다.

### 3. 대안 검토 (Alternatives)

- **대안 A: Scrapy 등 크롤링 프레임워크**
  스케줄러·파이프라인·미들웨어·동시성 관리를 제공한다. 그러나 그 기능들이 해결하는 문제
  (대규모 동시 크롤, 큐 관리, 분산)가 우리에게 없다. 대상이 29곳이고 호스트당 3초 간격을
  지켜야 하므로 동시성 자체가 이득이 아니다. 프레임워크 규약(Spider·Item·Pipeline)에 맞추는
  비용만 남는다. `requests` + `BeautifulSoup`이면 `fetch.py` 160줄로 끝난다.

- **대안 B: Playwright·Selenium 등 헤드리스 브라우저**
  JS 렌더링이 필요한 사이트를 다룰 수 있다. 그러나 실제 출처인 티스토리 블로그는 본문이
  서버 렌더링이라 필요가 없다. 브라우저 바이너리 의존성, 실행 시간, 메모리가 순수 비용이다.
  나중에 JS 렌더링이 필요한 출처가 생기면 `fetch.py` 안에서만 교체하면 된다.

- **대안 C: 정규식·셀렉터만으로 전부 파싱 (LLM 없이)**
  비용이 0이고 결정적이다. 그러나 위에 적은 표현 다양성 때문에 블로그마다 규칙을 새로 짜야
  하고, 새 출처가 추가될 때마다 코드가 늘어난다. 실제로 날짜 표현만 4종 이상을 확인했다.
  유지보수 비용이 수집 대상 수에 비례해 늘어나는 구조라 기각했다.

- **대안 D: LLM에게 판정까지 맡기기 (에이전트로 크롤링 전체 위임)**
  구현이 가장 짧다. 그러나 LLM이 URL을 지어내거나 다른 대학 글을 채택해도 검출할 방법이
  없어진다. 축제 데이터는 틀리면 사용자가 헛걸음하므로, **판정 경로에 검증 가능한 코드가
  반드시 있어야 한다**고 보고 기각했다. 대신 `verify()`로 LLM 출력을 되짚는 구조를 택했다.

- **대안 E: Anthropic API SDK 직접 호출 (구독 CLI 대신)**
  토큰당 과금이라 비용이 투명하고, 프롬프트 캐싱을 직접 제어할 수 있다. 그러나 v1 시점에는
  **API 키 발급·비용 승인 절차 없이 즉시 시작할 수 있는 것**이 우선이었다. 구독 CLI는 이미
  로그인돼 있고 추가 과금이 없다. 대신 전환 비용을 0으로 만들어 두었다 — LLM 접점을
  `extract.call_claude()` 함수 하나로 한정하고, 시그니처를 바꾸지 않고 내부만 SDK 호출로
  교체할 수 있게 했다. (아래 "단점" 참고 — 이 대안은 재검토 대상이다.)

- **대안 F: 서버·서버리스 상시 실행**
  자동 스케줄링이 가능하다. 그러나 축제 데이터는 **연 1회 시즌 단위**로 갱신되고, 산출물은
  어차피 사람이 검수해야 한다. 상시 실행할 대상이 없어 배포·모니터링 비용만 생긴다.
  손으로 돌리는 로컬 배치로 두고, 배포 대상을 아예 만들지 않았다.

### 4. 결과 및 영향 (Consequences)

**장점**

- **의존성이 5개뿐이다** (`requests`·`beautifulsoup4`·`trafilatura`·`pydantic`·`pytest`).
  나머지는 표준 라이브러리(`csv`·`json`·`subprocess`·`urllib.robotparser`)로 해결된다.
  배포 대상이 없어 인프라 비용이 0이다.
- **표현 다양성을 코드로 떠안지 않는다.** 새 블로그가 나와도 파싱 규칙을 추가하지 않는다.
  LLM 프롬프트는 출처와 무관하게 하나다.
- **LLM이 이상한 답을 줘도 산출물에 실리지 않는다.** pydantic 스키마 검증(열거값은 `Literal`로
  선언) → 재시도 → `verify()` 역방향 검증 → flag 부여가 전부 코드다. 실측에서 `mismatch`·
  `no_candidate`가 실제로 걸러졌다.
- **교체 지점이 각각 한 곳이다.** LLM은 `call_claude()`, 수집은 `fetch.py`, 스키마는
  `schema.py`. 대안 A·B·E로 갈아탈 때 그 파일만 바뀐다.
- **재실행이 싸다.** 캐시가 유효한 대학은 LLM을 부르지 않아 29곳 재실행이 수 초에 끝난다.

**단점 및 위험 요소**

- **구독 CLI 호출의 고정 오버헤드가 크다.** 실측 결과 `claude -p` 호출 1건당 Claude Code 자체
  시스템 프롬프트 **39,492 토큰**이 매번 새로 실린다(2회 측정 모두 `cache_read: 0` — 호출 간
  캐시 재사용 없음). API 환산 **$0.395/호출**이고, 우리 프롬프트가 가장 큰 `extract`조차
  입력의 20%에 불과하다. 전체 재크롤 1회가 API 환산 $16~37이다. 구독에서는 과금이 없지만
  **세션 한도를 그만큼 소모하는 것이 크롤러가 중단되는 실제 원인**이다.
  → 대안 E(SDK 직접 호출)로 전환하면 이 오버헤드가 사라진다. 재검토 대상이다.
- **LLM 호출이 직렬이고 느리다.** 대학 1곳당 수십 초, 전체 30~50분. 병렬화하면 세션 한도에
  더 빨리 걸리고 중단 지점이 흐려져 지금은 순차로 둔다.
- **출처가 남의 블로그다.** 글이 삭제되면 재수집이 실패한다(캐시 폴백으로 완화). robots.txt와
  요청 간격을 지키는 것이 강제 조건이다.
- **결과가 결정적이지 않다.** 같은 본문에서 매번 같은 JSON이 나온다는 보장이 없다. 그래서
  사람 검수가 선택이 아니라 구조의 일부다.
- **`trafilatura`가 무거운 의존성을 끌고 온다** (`lxml` 등). 셀렉터가 실패할 때만 쓰는
  폴백인데 설치 비용은 항상 낸다. 대상 블로그가 몇 곳으로 굳으면 제거를 검토할 수 있다.
- **`pyproject.toml`이 없다.** `version.yml`의 `project_types`가 `basic`이며, 패키징이
  필요해지면 함께 바꿔야 한다.
