## 📌 리뷰어가 알아야 할 것

**① 이슈에 없던 가드를 하나 더 넣었습니다.** 이슈는 중복 대학 가드만 요구했는데, **구 시드 스키마 감지**를 함께 넣었습니다. 좌표 컬럼 없는 시드로 돌리면 `KeyError`로 죽거나 좌표가 조용히 빈 값으로 나가는데, 후자가 이 저장소가 세 번 겪은 유형입니다. **구현 직후 실제로 값을 했습니다** — 기존 테스트 3건이 실패했고 원인이 코드가 아니라 아직 마이그레이션 안 된 실물 시드였습니다.

**② `record["latitude"]`를 엄격하게 뒀습니다.** `.get("latitude", "")` 폴백이면 픽스처 11곳을 안 고쳐도 됐지만, **좌표 없는 record가 조용히 빈 값으로 나가는 경로**가 열립니다. 캐시 히트 테스트가 막으려는 실패와 같은 모양이라 필수 필드로 뒀습니다.

**③ 캐시 히트 갱신이 두 곳입니다** — `process_row`의 히트 분기와 `_keep_stale_on_failure`. 빠뜨리면 **기존 캐시로 히트한 대학의 좌표가 빈 값으로 나가고, 오류 없이 결과만 틀립니다.** 회귀 테스트(`test_process_row_cache_hit_refreshes_coordinates`)가 좌표 없이 기록된 구 캐시로 히트시켜 이것을 잡습니다.

**④ ⚠️ 좌표 값은 캠퍼스 중심·정문 기준 초안이며 지도 검수가 필요합니다.** 국내 범위(위도 33~39 · 경도 124~132) 자체 검사는 통과했지만 그건 **「한국 안에 있다」까지만** 보증합니다. 좌표는 값이 틀려도 형식이 맞아 보여서 지도에 찍히기 전까지 아무도 모릅니다. 머지 전에 확인해 주세요.

**⑤ 전 29행의 `import_key`가 바뀝니다.** 백엔드 E2는 비어 있음을 공개 API로 확인했습니다(`/api/festivals/upcoming`·`/recent` 둘 다 `{"items":[]}`) — 정리할 데이터가 없습니다.

### 범위 밖 (별건)

임포트 예측은 `flag=OK` 26건 중 **성공 23건 · 발행 게이트 통과 20건**입니다. 좌표가 없을 때는 **0건**이었습니다. 남은 6건은 좌표·키와 무관한 기존 문제입니다:

- 건국대(축제명 빔) · 한국외대(시작일 빔) · 이화여대(종료일 빔) → 축제 행 `INVALID`
- 서울시립대(라인업 6행 전부 `day` 빔) · 고려대 · 성신여대(라인업 0행) → `LINEUP_EMPTY`

**업로드 리허설은 돌리지 않았습니다** — 위 예측은 백엔드 검증 규칙을 재현한 결과이지 실물 응답이 아닙니다.
